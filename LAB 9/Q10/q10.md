# Q10 — Greedy Superstring Conjecture (Open Problem)

**File:** `q10.c`

## Problem

Given a set of $n$ strings $S = \{s_1, s_2, \ldots, s_n\}$, find the **shortest single string** that contains every $s_i$ as a substring. This is known as the **Shortest Superstring Problem (SSP)**.

SSP is **NP-hard** — no known polynomial-time algorithm produces the exact optimum for large $n$. The standard approach is the **greedy approximation**:

> Repeatedly merge the pair of strings with the **maximum suffix-prefix overlap**, until only one string remains.

## Historical Context — Open Problem

The greedy algorithm was conjectured for nearly **40 years** to be a **2-approximation** — i.e. its output length is at most twice the optimum:

$$
\frac{\text{greedy length}}{\text{optimal length}} \le 2
$$

In **September 2026**, an arXiv paper *"Disproving the Greedy Superstring Conjecture"* constructed explicit counterexamples for even-length strings with $k \ge 10$, showing the ratio can be at least:

$$
\frac{9k + 2}{4k + 4} \xrightarrow{k \to \infty} \frac{9}{4} = 2.25
$$

This disproves the long-standing 2-approximation claim. The paper is not yet peer-reviewed, but the result has generated significant discussion in the theory community.

## Input

- $n$ — number of strings
- $n$ whitespace-delimited strings

## Output

- Each greedy merge step with its overlap
- Final greedy superstring

## Approach

Repeatedly, at each step:

1. For every ordered pair $(i, j)$ with $i < j$, compute both:
   - `forward = overlap(s[i], s[j])`
   - `backward = overlap(s[j], s[i])`
2. Pick the pair and direction with the **largest overlap**.
3. Merge that pair into one string (append the non-overlapping suffix).
4. Replace the pair with the merged string; repeat until one string remains.

Formally, the overlap function is:

$$
\text{overlap}(a, b) = \max \Big\{ k \ \Big|\ \text{suffix}_k(a) = \text{prefix}_k(b) \Big\}
$$

And the merge operation is:

$$
\text{merge}(a, b) = a + b[\text{overlap}(a,b) \dots |b|-1]
$$

### Why this isn't optimal

Greedy can make locally best choices that lock it into globally suboptimal merges. The September 2026 counterexamples exploit exactly this: pairs of strings with a "tempting" overlap that turns out to be a trap.

## Complexity

- **Time:** $O(n^3 \cdot T^2)$ — $O(n^2)$ pairs per merge, $n$ merges, $O(T)$ work per overlap computation where $T$ is the total input length
- **Space:** $O(T + n)$ — active strings and their storage

## Compile and Run

```bash
gcc -std=c99 -Wall -Wextra q10.c -o q10
./q10
```

## Sample

Input:

```
3
abc
bcd
cde
```

Output:

```
Merge 1 (overlap 2): abcd
Merge 2 (overlap 2): abcde
Greedy superstring: abcde
```

### Walk-through

1. Overlaps: `abc` + `bcd` share `bc` (overlap 2). `bcd` + `cde` share `cd` (overlap 2). Both are equally good.
2. Merge `abc` + `bcd` → `abcd`.
3. Now strings are `abcd` and `cde`. Overlap = `cd` (length 2). Merge → `abcde`.
4. Result: `abcde` (length 5). Optimal is also 5 here — but not always.

## Note on Optimality

For the sample above, greedy gives the optimal answer. In general it does **not**. If your goal is the true shortest superstring, you'd need exact algorithms like Held-Karp TSP over overlap costs, which run in $O(2^n \cdot n^2)$ — exponential.
