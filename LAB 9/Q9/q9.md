# Q9 — Optimal Alphabetic Binary Tree (interval DP)

**File:** `q9.c`

## Problem

Given $n$ ordered weights $w_0, w_1, \ldots, w_{n-1}$, build a binary tree whose leaves keep the input order intact (an **alphabetic** tree). Minimise the weighted path length:

$$
\text{cost} = \sum_{i=0}^{n-1} w_i \cdot \text{depth}(i)
$$

where `depth(i)` is the number of edges from the root to leaf $i$.

## Input

- Menu choice `1`, then $n$ and $n$ positive ordered weights
- Menu choice `0` to exit

## Output

- Minimum weighted path length
- Alphabetic tree structure (parenthesised)
- Per-index weight and depth

## Approach

**Interval DP** over ranges $[i, j]$ of the ordered leaves.

Define:

$$
\text{dp}[i][j] = \text{minimum cost of an alphabetic tree over weights } i \ldots j
$$

Base case — a single leaf has depth 0 relative to itself:

$$
\text{dp}[i][i] = 0
$$

For any interval of length $\ge 2$, choose a split point $k \in [i, j-1]$. The left subtree handles $[i, k]$, the right handles $[k+1, j]$. Every leaf in $[i, j]$ gains one extra edge of depth, so we add the total weight of the range:

$$
\text{dp}[i][j] = \min_{i \le k < j} \Big( \text{dp}[i][k] + \text{dp}[k+1][j] \Big) + \sum_{t=i}^{j} w_t
$$

The range sum is precomputed with a prefix-sum array so each transition is $O(1)$.

Alongside, `split[i][j]` stores the winning $k$, so the tree can be printed recursively and each leaf's depth recovered.

### Note on naming

This is the **dynamic-programming form** of the optimal alphabetic tree, running in $O(n^3)$. The classic **Hu-Tucker** greedy algorithm achieves the same optimum in $O(n \log n)$ but is significantly more complex to implement. The DP here is the standard textbook approach for labs.

## Complexity

- **Time:** $O(n^3)$ — $O(n^2)$ intervals, each trying $O(n)$ split points
- **Space:** $O(n^2)$ — `dp[][]` and `split[][]` tables

## Compile and Run

```bash
gcc -std=c99 -Wall -Wextra q9.c -o q9
./q9
```

## Sample

Input:

```
1
3 3 1 2
0
```

Output:

```
Minimum weighted depth: 9
Alphabetic tree: (1,(2,3))
Index Weight Depth
1 3 1
2 1 2
3 2 2
```

### Walk-through

Weights: $w = [3, 1, 2]$.

Compare the two possible splits for interval $[0, 2]$:

- **Split at $k = 0$**: tree is $(w_0, (w_1, w_2))$, i.e. `(1, (2, 3))`.
  - Depth of $w_0 = 1$, depth of $w_1 = 2$, depth of $w_2 = 2$.
  - Cost $= 3 \cdot 1 + 1 \cdot 2 + 2 \cdot 2 = 3 + 2 + 4 = 9$.

- **Split at $k = 1$**: tree is $((w_0, w_1), w_2)$, i.e. `((1, 2), 3)`.
  - Depth of $w_0 = 2$, depth of $w_1 = 2$, depth of $w_2 = 1$.
  - Cost $= 3 \cdot 2 + 1 \cdot 2 + 2 \cdot 1 = 6 + 2 + 2 = 10$.

The DP picks $k = 0$, giving the minimum cost $9$.
