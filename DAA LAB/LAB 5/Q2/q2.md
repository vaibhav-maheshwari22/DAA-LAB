# Question 2: Find K'th Smallest Element Without Sorting

## Problem Statement
Find the K'th smallest element in a given list of N numbers without sorting the list. Do the complexity analysis of your algorithm.

## Approach & Features
1. **Quickselect Algorithm:** Similar to the median finding approach, we utilize Quickselect to avoid the overhead of a full $O(N \log N)$ sort.
2. **Target Index:** For the $K^{th}$ smallest element, the target index is strictly $K - 1$ (assuming 0-based indexing).
3. **Selective Partitioning:** The array is partitioned around a chosen pivot. We compare the pivot's final index with $K - 1$ and selectively recurse into only the relevant half of the array.
4. **User Input:** The program takes $N$ array elements manually from the user, followed by the target value $K$ (with bounds validation).

## Complexity Analysis
* **Time Complexity:** 
  * **Average & Best Case:** $O(N)$. The expected running time is linear because the search space roughly halves at each step: $T(N) = T(N/2) + O(N) = O(N)$.
  * **Worst Case:** $O(N^2)$. This worst-case quadratic behavior happens if the chosen pivot consistently fails to divide the array evenly (e.g., already sorted array with a bad pivot strategy).
* **Space Complexity:** $O(1)$ auxiliary space since it operates entirely in-place. Stack memory usage is $O(\log N)$ expected and $O(N)$ in the worst case.
