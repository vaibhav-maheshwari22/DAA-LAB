# Question 6: Use of Loop Invariants in Sorting (Selection Sort)

## Problem Statement
Consider sorting $n$ numbers stored in an array $A[1 \dots n]$ by first finding the smallest element of $A[1 \dots n]$ and exchanging it with the element in $A[1]$. Then, find the smallest element of $A[2 \dots n]$, and exchange it with $A[2]$. Continue in this manner for the first $(n - 1)$ elements of $A$. 
* Write a pseudocode for this algorithm.
* What loop invariant does this algorithm maintain? 
* Why does it need to run for only the first $(n − 1)$ elements? 
* Give the worst-case and best-case running time in $\Theta$-notation. 
* Implement in C to validate.

---

## 1. Pseudocode
*(Note: The pseudocode uses 1-based indexing as per the problem statement, while the C implementation uses 0-based indexing).*

```text
SelectionSort(A, n):
  For i = 1 to n - 1:
    minIndex = i
    For j = i + 1 to n:
      If A[j] < A[minIndex]:
        minIndex = j
    Swap A[i] with A[minIndex]

```
## 2. Loop Invariant Analysis
Generally, loop invariants are used to prove an algorithm’s correctness by demonstrating initialisation, maintenance, and termination.

**The Loop Invariant:**
At the start of each iteration $i$ of the outer loop, the subarray $A[1 \dots i-1]$ contains the $(i-1)$ smallest elements of the original array, strictly in sorted order.

*   **Initialisation:** Before the first iteration ($i = 1$), the subarray $A[1 \dots 0]$ is empty. An empty array trivially contains the $0$ smallest elements in sorted order. Thus, the invariant holds before the loop begins.
*   **Maintenance:** During iteration $i$, the algorithm searches the remaining unsorted suffix $A[i \dots n]$ for the absolute minimum element and swaps it into position $A[i]$. Because $A[1 \dots i-1]$ already holds the smallest elements, placing the next smallest element at $A[i]$ correctly grows the sorted prefix by one element. The invariant is maintained for the next iteration.
*   **Termination:** The loop terminates when $i = n$. At this point, the prefix $A[1 \dots n-1]$ contains the $(n-1)$ smallest elements of the array in sorted order.

## 3. Why run for only the first $(n-1)$ elements?
If the algorithm successfully sorts and places the $(n-1)$ smallest elements in their exact correct positions at the front of the array, the single remaining element left in $A[n]$ must logically be the absolute largest element of the entire array. It is naturally left in its correct final position at the very end. Therefore, running a final pass for the $n^{th}$ element is mathematically redundant and unnecessary.

## 4. Time Complexity Analysis
*   **Worst-case running time:** $\Theta(n^2)$
*   **Best-case running time:** $\Theta(n^2)$

**Is the best-case any better?**
No, the best-case running time is not any better. Selection sort is completely blind to the initial ordering of the array. Even if the array is already perfectly sorted, the inner loop must still scan the entire remaining unsorted suffix $A[i \dots n]$ to verify that $A[i]$ is indeed the minimum. No early exit is possible, meaning the total number of comparisons is always exactly $\frac{n(n-1)}{2}$, making it strictly $\Theta(n^2)$ in all cases.
